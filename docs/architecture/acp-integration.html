01 / The decision

我们引入的不是另一个 SDK，
而是一条稳定边界。

OpenAPI 已具备 Longbridge Agent 能力。下一步的关键不是把接口复制到三个客户端，而是把变化最频繁的 Agent 能力封装在一个可协商的协议边界后。

“桌面端直接链接 Rust crate；CLI 只负责对外 stdio。两条路径复用同一个 ACP Agent 实现。”
核心选择：复用协议组件，不复用 CLI 进程。

明确不做

  • 桌面端不启动或嵌入 longbridge CLI
  • crate 不读取 CLI 的 OAuth 与全局配置
  • 不把 Longbridge 私有事件泄漏给 AI Chat
  • 当前阶段不扩大为网络 ACP Gateway

03 / Real host boundaries

两个桌面产品，两个组合根。

相邻仓库的实际技术边界不同。ACP crate 保持 UI 无关；每个产品在自己的主进程/原生层负责构造配置、权限确认和生命周期。

PRO

Longbridge Pro

longbridge-gpui 是完整 Rust workspace；ai_agent 已实现私有 Babbage API 的 ACP backend 与统一 Chat facade，ai_panel 已可选择 LongbridgeAI ACP、Codex、Claude，并消费标准化文本、思考与工具事件。

  • 直接跟踪独立 longbridge-ai-acp 仓库 main 分支
  • 由 Pro 的 config / engine 注入授权与 endpoint
  • ai_panel 消费统一 ACP session updates
AI

LongbridgeAI Desktop

React 对话 UI 运行于 Tauri WebView。Rust 壳已把宿主私有 Babbage API 实现为进程内 AgentBackend，并以同一 session bridge 托管 LongbridgeAI、Codex 与 Claude；endpoint、环境和登录 session 仍属于桌面宿主。

  • Tauri command 只传结构化会话事件
  • ACP 权限选项已回到产品确认 UI；私有 API HITL 通过宿主 /continue API 续跑
  • 外部 Agent 生命周期由 Rust 层托管
现状迁移重点：Longbridge Pro 已有成熟的 ai_agent → ai_panel SSE 事件链路。ACP 接入不应平行复制一套 UI，而应让 ai_panel 面向统一会话事件，并逐步把 Longbridge 私有网络协议收敛到 Adapter 内。

05 / Rich content

图表不降成截图，协议也不假装懂图表。

ACP v1 没有通用 Chart 类型。Longbridge 采用双轨表达：标准客户端读取 Markdown、SVG image、公开链接与 ResourceLink；Longbridge 客户端读取 longbridge.ai/event 原始事件并继续复用原有 Chat elements。配对 fallback 带去重标记。

STANDARD ACP

始终可读

  • 图表转 GFM Markdown 表格
  • 安全 SVG 转 image/svg+xml
  • HTML 转有界纯文本摘要
  • Widget 转公开链接 / ResourceLink
  • 不回显私有 JSON、HTML 或 SVG 源码
RICH ENVELOPE

结构化保真

  • version + content_id
  • kind + MIME + data
  • snapshot 覆盖，避免重复卡片
  • 扩展不改变授权边界
LONGBridge UI

原 Chat 体验

  • PortAI：24 类规范化可视化类型
  • GPUI：柱/条/线/面积/饼/雷达/双轴
  • widget、引用、股票与 artifact
  • 能力不足时稳定降级
application/vnd.longbridge.chart+json

柱状、折线、面积、饼图、雷达、双轴，以及地图、关系图等完整结构化配置。

text/html · image/svg+xml

HTML/SVG 继续走既有沙箱与内容安全策略；ACP metadata 不授予新的执行权限。

widget:// · artifact

已知 widget 复用 Quote/Comparison 等 Chat elements；未知资源退化为可点击链接和说明。

unknown → fallback

未知版本、kind 或 chart type 不终止回答；展示 Markdown/JSON，保证数据永远不消失。

关键不变量：结构化 payload 是事实源，fallback 与其数值语义必须一致；围栏完整后才发布 rich snapshot，同一 content_id 只更新、不重复追加。
06 / Trust & ownership

授权不穿透，职责不漂移。

统一协议不等于统一凭证。最重要的安全边界是：谁启动 Agent，谁提供该 Agent 的配置；适配 crate 只消费，不发现、不持久化、不刷新。

HOST OWNS

产品宿主

  • OAuth / token 生命周期
  • API endpoint 与环境选择
  • 可选 Agent ID（CLI 默认 chatbot）
  • 权限确认 UI
  • 外部进程 allowlist
CRATE OWNS

longbridge-ai-acp

  • ACP initialize 与能力协商
  • session / prompt / cancel
  • 宿主后端事件 ↔ ACP 映射
  • 通用会话状态封装
  • 一致的结构化错误
AGENT OWNS

Codex / Claude

  • Provider 登录与模型配置
  • 原生工具实现
  • 自身会话语义
  • stderr 诊断输出
  • 支持的 capability 集合
impl AgentBackend

CLI 实现 OpenAPI Adapter；桌面端分别实现私有 API Adapter。ACP crate 不持有 endpoint 或凭证。

initialize(v1)

只宣告真实实现的 capability；未知协议版本不伪装成功。

session/update

文本、思考与工具事件统一回流，UI 不依赖 Longbridge 私有类型。

session/cancel

取消必须到达正在运行的 stream，返回明确的 Cancelled stop reason。

07 / Delivery path

按可验证的纵向链路推进。

先证明协议与边界，再做多产品接入。每一阶段都产生可运行、可演示、可回归的能力，而不是等待“大集成”。

PHASE 1

PHASE 3

The architectural outcome

一个 LongbridgeAI Adapter，
覆盖所有入口。
